# 兼容性与验证范围

## 当前支持

| 项目 | 范围 |
| --- | --- |
| 制造商（BIOS 返回值） | `HASEE Computer` |
| 产品名（BIOS 返回值） | `CNP6S` |
| 系统目标 | Windows 10/11 x64 |
| GUI 控制通道 | 最多两个风扇，界面标记为 CPU / GPU |
| 权限 | 管理员，使用随附 InpOutx64 端口访问驱动 |

本项目原有 EC 控制核心曾在该机型验证。CPU/GPU 名称是本机通道映射，不能推广到其他机型。Windows 10/11 是运行目标，不表示每个系统版本均经过实机测试。

## 1.1.x 验证记录

- 配置迁移、全部模式组合保存/读取、独立及同步手动控制、曲线共享及还原：自动化模拟测试。
- Tk 界面构建、就绪后恢复模式、退出恢复自动控制：使用模拟控制器测试。
- 95°C 进入全速保护、88°C 解除、重新配置保持保护、传感器异常回退：模拟测试。
- 构建文件、ZIP 完整性与 SHA256：发布前检查。
- 本轮新增功能未进行真实硬件调速或高负载温度验证；模拟通过不等同于硬件认证。

## 其他型号

默认机型保护位于 `platform_guard.py`。`--allow-unsupported` 只绕过型号检查，不检测或证明 EC 协议兼容。不要通过关闭机型保护来试验未知寄存器。

适配贡献应提供制造商/产品名、协议来源、风扇通道映射、温度与 RPM 读取验证、自动恢复验证及实际测试范围。不要提交序列号、完整系统转储或个人配置。

## 运行与恢复

- 同一时间仅使用一个 EC 或风扇控制程序。
- 退出应用会逐个尝试恢复 EC 自动；下次启动仍可恢复保存的用户选择。
- 控制/传感器异常会尝试恢复自动，错误会显示在状态栏。恢复失败也会显示，不能保证硬件在通信故障时接受命令。
- GUI 的高温保护由进程中的轮询实现，并非固件保护；强制结束进程、断电或系统故障时，Python 的清理流程不保证执行。
- CLI `clevo_fan.py` 是开发接口；GUI 的模式记忆和高温保护由 `fan_policy.py` 提供，CLI 不具备相同保护策略。
